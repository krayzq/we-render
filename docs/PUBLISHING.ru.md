# Опубликовать we-render

Исходники и оформление подготовлены. Репозиторий в твоём аккаунте **ещё не создан**.
Первый выпуск — **beta / prerelease**: настоящая сцена с установленным Linux-движком
здесь ещё не проверена. Не публикуй его под обещанием «любые обои без ограничений».

## 1. Распакуй исходники

Скачай `we-render-0.1.0b1-source.zip`, распакуй и открой терминал в папке `we-render`.
В ней должны лежать `README.md`, `install.sh`, `we_render/` и `tools/`.
Не загружай сам ZIP как единственный файл репозитория.

## 2. Проверь на своём компьютере

```sh
./install.sh --deps
~/.local/bin/we-render --doctor
~/.local/bin/we-render /путь/к/папке/обоев --duration 2
```

Убедись, что в ролике действительно есть дождь, листья и другие ожидаемые эффекты.
Ошибка или отсутствие части эффектов означает, что совместимость ещё надо исправлять.
`--doctor` проверяет зависимости, но не является проверкой визуальной правильности.

## 3. Загрузка одной командой

На Arch установи Git и официальный GitHub CLI:

```sh
sudo pacman -S --needed git github-cli
python3 tools/publish.py
```

Скрипт откроет авторизацию GitHub при необходимости, определит твой ник,
предложит создать **публичный** репозиторий `we-render`, подготовит первый коммит
с GitHub noreply-почтой, загрузит код и отправит тег версии. Он покажет список файлов
и запросит подтверждение. Пароль GitHub в скрипт не вставляется.

README с обложкой сразу станет главной страницей проекта. Отдельный сайт не нужен.
Если имя уже занято **в твоём аккаунте**: `python3 tools/publish.py --name другое-имя`.
Посмотреть план без изменений: `python3 tools/publish.py --dry-run`.

## 4. Файл для скачивания

Открой **Actions → Draft release**. После успешной проверки открой **Releases**,
проверь черновик `v0.1.0b1` и нажми **Publish release**, сохранив **pre-release**.
В нём должны быть `we-render.pyz`, установочный Linux ZIP, исходники и SHA256SUMS.
GitHub Actions ещё не запускались в твоём аккаунте; не считай успех заранее подтверждённым.

Обычным пользователям нужен **Linux ZIP**, не автоматический `Source code (zip)`.

## Если скрипт прервался

Он не удаляет уже сделанную работу и не делает force-push. Если `.git` уже появился,
сначала `git status` и `git remote -v`. Не удаляй репозиторий наугад.
Если ты остановился после списка файлов, но до первого коммита: проверь
`git diff --cached --stat`, затем `git commit -m "Initial WE Render beta"`.
При отказе из-за workflow-разрешения: `gh auth refresh -h github.com -s workflow`.
Если коммит есть, но удалённый репозиторий ещё НЕ создан, выполни:

```sh
gh repo create we-render --public --source=. --remote=origin --push
```

Если `origin` уже правильно настроен на ТВОЙ репозиторий: `git push -u origin main`.
Тег отправляется только один раз:

```sh
git tag -a v0.1.0b1 -m "WE Render 0.1.0b1"
git push origin v0.1.0b1
```

Если тег уже существует, повторять первую команду не надо. Если Actions недоступен,
`python3 tools/build.py` создаст файлы в `dist/`: их можно прикрепить вручную через
**Releases → Draft a new release**, взяв текст из `docs/RELEASE.md`.

Перед отправкой проверь, что в коде нет ключей, `.env`, личных файлов, исходных обоев
или proprietary `assets`. Логи тоже могут содержать личные пути. Подготовленный ZIP
не содержит твоих обоев, ресурсов Wallpaper Engine или файлов шрифтов.
